Read `${CLAUDE_PLUGIN_ROOT}/ROUTING.md` in full — that is the content you are
installing. Do not paraphrase or summarize it; the bytes that go into the
consuming repo must match the shipped file.

## 1. Find or create the target file

Target: `.claude/CLAUDE.md` in the current repository (not the plugin's own
tree).

- **If `.claude/CLAUDE.md` does not exist**, create it with a one-line pointer
  at the top (`Agent routing policy for this repository.`) followed by the
  marked block below.
- **If `.claude/CLAUDE.md` already exists**, never overwrite it. Search it for
  a `<!-- sdlc-suite:routing:start -->` marker:
  - **Marker found** — replace only the text between
    `<!-- sdlc-suite:routing:start -->` and `<!-- sdlc-suite:routing:end -->`
    with the current `ROUTING.md` content. Everything outside the markers is
    the adopter's own instance configuration and must be left untouched.
  - **No marker** — append the marked block to the end of the file, after a
    blank line. Do not touch anything already in the file.

The marked block is `ROUTING.md`'s content wrapped exactly like this:

```
<!-- sdlc-suite:routing:start -->
(the full text of ROUTING.md)
<!-- sdlc-suite:routing:end -->
```

## 2. Ask the four instance questions

Once the routing policy is installed, ask the user — do not guess or default
any of these:

1. **Which trees are live here?** In this plugin's own source repo that's
   `sdlc-suite/` (hand-edited) plus generated copies; in a typical consuming
   repo it is usually just the plugin install, or a single vendored copy. Ask
   which directories in *this* repo are actually hand-edited agent/skill
   definitions, if any.
2. **What is the canonical edit path?** If more than one tree carries agent or
   skill definitions in this repo, which one does a contributor edit, and how
   do the others get updated — regenerated by a script, copied by hand, or
   genuinely independent?
3. **What is the project name for the memory root?** Agents in this suite
   read and write `.claude/memory/<project>/`. Get the project name to use for
   `<project>` so memory does not collide with another project's on a shared
   machine.
4. **Which harness is this repo targeting?** Claude Code (plugin or project
   tree), Command Code, Kimi Code, or another — this determines which of the
   generated ports (if any) are relevant here at all.

## 3. Record the answers

Append the four answers to `.claude/CLAUDE.md`, below the routing-policy
block, under a heading such as `## Repository layout` or `## Instance
configuration` — whatever fits the file's existing structure. This is where
this repository's own CRLF/line-ending hazards, tree-duplication hazards, or
other local operational notes belong; `ROUTING.md` deliberately does not carry
them because they are specific to the repository that discovered them.

Do not run this command's edits through the `Workflow` tool — it is a direct
file operation (read one file, write or append to another, then ask
questions), not a multi-agent orchestration, so there is no `workflows/*.js`
script backing it.
