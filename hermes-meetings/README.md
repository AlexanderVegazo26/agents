# Hermes Meetings

Hermes joins your meetings, transcribes them, takes notes, and generates
questions from the discussion in realtime. This directory is the integration:
a self-hosted open-source meeting-bot stack (Vexa, Apache-2.0) wired into
Hermes Agent's MCP toolset, skills, webhooks, and cron.

`INVESTIGATION.md` is the original tool survey and design rationale. This
README documents what is actually implemented on this machine.

## Architecture

```
Meeting (Google Meet / Teams / Zoom / Jitsi)
   │  bot joins as a participant ("Hermes")
   ▼
Vexa Lite (Docker, self-hosted)        vexa-lite-whisper (faster-whisper, CPU)
   │  speaker-attributed transcript segments (REST + Redis)
   ▼
Vexa MCP service (standalone container, 127.0.0.1:18010/mcp)
   ▼
Hermes Agent
   ├─ MCP toolset "vexa" (send/stop bot, transcripts, chat, recordings, speak…)
   ├─ skills: meeting-bot-ops, meeting-live-questions, meeting-notes
   ├─ webhook routes: meeting-live-questions, meeting-notes
   └─ cron poller (~/.hermes/scripts/vexa-poll.py, planned, not installed yet)
   ▼
You (Telegram) + notes on disk
```

One rule shapes everything: the bot is ears and voice, Hermes is the brain.
Vexa runs no model of its own during a meeting — every question, note, and
summary is generated by Hermes.

## Setup (to reproduce on a fresh machine)

```bash
# 1. Meeting-bot stack (Docker required)
git clone https://github.com/Vexa-ai/vexa.git
cd vexa && make -C deploy/lite all LOCAL_STT=1 WHISPER_MODEL=Systran/faster-whisper-small.en

# 2. Standalone MCP service (Lite does not bundle it)
docker build -t vexa-mcp:local core/meetings/services/mcp
docker run -d --name vexa-mcp --network vexa-lite-net --restart unless-stopped \
  -e GATEWAY_URL=http://vexa-lite:8056 -e PORT=8010 \
  -p 127.0.0.1:18010:8010 vexa-mcp:local

# 3. API key — minted on first boot into the postgres sidecar:
docker exec vexa-lite-postgres psql -U postgres -d vexa \
  -t -c "SELECT token FROM api_tokens ORDER BY created_at DESC LIMIT 1;"

# 4. Hermes
echo 'MCP_VEXA_API_KEY=<that key>' >> ~/.hermes/.env
hermes mcp add vexa --url http://127.0.0.1:18010/mcp --auth header
# then ensure config.yaml's vexa entry carries:
#   headers: { Authorization: Bearer ${MCP_VEXA_API_KEY} }
# skills are symlinked, not copied, so this repo stays canonical (no drift).
# run from this directory (hermes-meetings/):
for s in meeting-bot-ops meeting-live-questions meeting-notes; do
  ln -sfn "$PWD/skills/$s" ~/.hermes/skills/$s
done

# verify
hermes mcp test vexa
hermes chat -t vexa   # "call get_bot_status" should return the running-bots list
```

## Using it

In any Hermes session (or with `/meeting-bot-ops`):

- "Join the meeting at <Meet/Zoom/Teams/Jitsi URL> as Hermes" — Hermes uses
  `parse_meeting_link` + `request_meeting_bot`.
- "What's happening in the meeting right now?" — `get_meeting_transcript`.
- "Leave the meeting" — `stop_bot`.
- Realtime questions: once the poller exists it will post transcript deltas
  to the `meeting-live-questions` webhook route. Until then, ask "what should
  I ask?" mid-call and Hermes replies on Telegram with up to 3 questions.
- Meeting notes: "notes for that call" runs `meeting-notes`, which writes
  structured notes (summary, decisions, action items with owners, open
  questions) to `~/.hermes/data/vexa-notes/` and replies with a compact
  summary.

## Status (honest)

Working and verified: stack deployment, local CPU transcription, MCP toolset
with auth, all three skills, Hermes-to-Vexa tool calls.

In progress / next: webhook routes + `vexa-poll.py` cron loop (last wiring
step), then an end-to-end test against a live Jitsi/Meet call.

Known limits: `update_bot_config` is not in the Vexa open core (it may 404).
In-call speech (`speak_in_meeting`) works through a local patch
(`vexa-lite:v0.12.28-voice`, VoiceStudio; see
`~/AI/engines/vexa-lite/voice-patch/README.md`). The transcription model is
`faster-whisper-small.en`, which is English-only, so Spanish calls need a
multilingual model first. Attribution
is dropped (empty speaker) rather than guessed under crosstalk. CPU
transcription lags a realtime feed by design on this box; the question cadence
is throttled to match.
