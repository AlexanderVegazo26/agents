# Hermes Meetings

Hermes joins your meetings, transcribes them, takes notes, and generates
questions from the discussion in realtime. This directory is the integration:
a self-hosted open-source meeting-bot stack (Vexa, Apache-2.0) wired into
Hermes Agent's MCP toolset, skills, webhooks, and cron.

`INVESTIGATION.md` is the original tool survey and design rationale. This
README documents what is actually implemented on this machine.

## Architecture

```
Meeting (Google Meet / Teams / Zoom / Jitsi)
   │  bot joins as a participant ("Hermes")
   ▼
Vexa Lite (Docker, self-hosted)        vexa-lite-whisper (faster-whisper, CPU)
   │  speaker-attributed transcript segments (REST + Redis)
   ▼
Vexa MCP service (standalone container, 127.0.0.1:18010/mcp)
   ▼
Hermes Agent
   ├─ MCP toolset "vexa" (14 tools: send/stop bot, transcripts, chat, recordings, speak…)
   ├─ skills: meeting-bot-ops, meeting-live-questions, meeting-notes
   ├─ webhook route: vexa-live (loaded by the gateway; nothing posts to it yet)
   ├─ cron poller (~/.hermes/scripts/vexa-poll.py, planned, not installed yet)
   ├─ in-call loop: vexa-agent.py (decides → speaks → writes in the chat)
   ├─ the bot's own browser over CDP (vexa-cdp.py) — acts in the meeting
   └─ stack control: ~/.hermes/scripts/vexa-stack.sh {start|stop|status}
   ▼
You (Telegram) + notes on disk
```

One rule shapes everything: the bot is ears and voice, Hermes is the brain.
Vexa runs no model of its own during a meeting — every question, note, and
summary is generated by Hermes.

## Setup (to reproduce on a fresh machine)

```bash
# 1. Meeting-bot stack (Docker required)
git clone https://github.com/Vexa-ai/vexa.git
cd vexa && make -C deploy/lite all LOCAL_STT=1 \
  WHISPER_MODEL=mobiuslabsgmbh/faster-whisper-large-v3-turbo

# 1b. In-call speech: build and apply the local voice patch on top.
#     Without it vexa-lite is the upstream image and speak_in_meeting 404s.
docker build -t vexa-lite:v0.12.28-voice ~/AI/engines/vexa-lite/voice-patch
~/AI/engines/vexa-lite/voice-patch/recreate-with-voice.sh

# 2. Standalone MCP service (Lite does not bundle it)
docker build -t vexa-mcp:local core/meetings/services/mcp
docker run -d --name vexa-mcp --network vexa-lite-net --restart unless-stopped \
  -e GATEWAY_URL=http://vexa-lite:8056 -e PORT=8010 \
  -p 127.0.0.1:18010:8010 vexa-mcp:local

# 3. API key — minted on first boot into the postgres sidecar:
docker exec vexa-lite-postgres psql -U postgres -d vexa \
  -t -c "SELECT token FROM api_tokens ORDER BY created_at DESC LIMIT 1;"

# 4. Hermes
echo 'MCP_VEXA_API_KEY=<that key>' >> ~/.hermes/.env
hermes mcp add vexa --url http://127.0.0.1:18010/mcp --auth header
# then ensure config.yaml's vexa entry carries:
#   headers: { Authorization: Bearer ${MCP_VEXA_API_KEY} }
# skills are symlinked, not copied, so this repo stays canonical (no drift).
# run from this directory (hermes-meetings/):
for s in meeting-bot-ops meeting-live-questions meeting-notes; do
  ln -sfn "$PWD/skills/$s" ~/.hermes/skills/$s
done
ln -sfn "$PWD/scripts/vexa-stack.sh" ~/.hermes/scripts/vexa-stack.sh

# verify
hermes mcp test vexa
hermes chat -t vexa   # "call get_bot_status" should return the running-bots list
```

> **Do not use `make -C deploy/lite up` for a routine restart.** It recreates
> `vexa-lite-whisper` with the Makefile default model (`tiny.en`, English-only)
> and recreates `vexa-lite` from the unpatched upstream image, which breaks
> Spanish transcription and in-call speech. Use `vexa-stack.sh start`, which
> only runs `docker start` on the existing containers.

## Running the stack

The stack is on demand — the containers carry `restart=no`, so a reboot leaves
them stopped. Start and stop it with:

```bash
~/.hermes/scripts/vexa-stack.sh start    # start in order, wait for gateway + STT + MCP
~/.hermes/scripts/vexa-stack.sh status   # container states + endpoint health
~/.hermes/scripts/vexa-stack.sh stop     # stop (data volumes are kept)
```

`start` waits for the gateway (`:8056`), whisper (`:8083`) and the MCP server
(`:18010`) to answer, so it is safe to run and then immediately use Hermes.
If a container is missing entirely, the script says so instead of rebuilding —
a rebuild is a deliberate operation (see Setup) and needs the voice patch.

## Using it

In any Hermes session (or with `/meeting-bot-ops`):

- "Join the meeting at <Meet/Zoom/Teams/Jitsi URL> as Hermes" — Hermes uses
  `parse_meeting_link` + `request_meeting_bot`.
- "What's happening in the meeting right now?" — `get_meeting_transcript`.
- "Leave the meeting" — `stop_bot`.
- Realtime questions: the `vexa-live` webhook route is registered and loaded,
  but no poller posts to it yet, so it never fires on its own. Until the
  poller exists, ask "what should I ask?" mid-call and Hermes replies on
  Telegram with up to 3 questions.
- Meeting notes: "notes for that call" runs `meeting-notes`, which writes
  structured notes (summary, decisions, action items with owners, open
  questions) to `~/.hermes/data/vexa-notes/` and replies with a compact
  summary.
- If the tools are unreachable, start the stack first:
  `~/.hermes/scripts/vexa-stack.sh start`.

## Status (honest)

Working and verified: stack deployment, on-demand start/stop, local CPU
transcription (multilingual), MCP toolset with auth, all three skills,
Hermes-to-Vexa tool calls, in-call speech route, and the CDP path that lets
the agent act in the meeting (chat) — the last one proven against a mock Meet
chat page, not yet against a live call.

In progress / next: an end-to-end test against a live Google Meet call (the
chat selectors are inferred from Meet's usual markup — `vexa-cdp.py discover`
prints the real DOM when the chain misses), then the `vexa-poll.py` poller
(until it exists the `vexa-live` route is inert).

Known limits: `update_bot_config` is not in the Vexa open core (it may 404).
In-call speech (`speak_in_meeting`) works through a local patch
(`vexa-lite:v0.12.28-voice`, VoiceStudio; see
`~/AI/engines/vexa-lite/voice-patch/README.md`) and needs VoiceStudio running
(`llamastash start voicestudio --wait`). The transcription model is
`mobiuslabsgmbh/faster-whisper-large-v3-turbo`, which handles Spanish and
English (verified 2026-11-26); names, numbers and jargon are still often
misheard, so cross-check against the meeting chat. Attribution
is dropped (empty speaker) rather than guessed under crosstalk. CPU
transcription lags a realtime feed by design on this box; the question cadence
is throttled to match. The `vexa-live` webhook still uses the legacy
body-only HMAC, which the gateway flags as replay-vulnerable.
